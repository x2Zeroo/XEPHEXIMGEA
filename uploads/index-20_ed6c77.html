Why Choose Luna

Onion-layered security for your Lua scripts

Defeat one layer and many more stand between an attacker and your source code. Luna is consistently updated with the state-of-the-art techniques.

Virtualization

Luna compiles your script into a custom bytecode format and generates a custom virtual machine in Lua that is unique to your script.

Bytecode Mutation

All information that isn't needed for the functionality of your script is stripped, randomized, or rewritten so attackers can't reconstruct the source.

Control Flow Scrambling

Many techniques obfuscate control flow in many places. Edge cases unexpectedly redirect the VM to a completely different path.

Encryption

Custom block cipher with CBC chaining, dynamic S-box, rotating XOR and positional offsets — all chained into a tamper-bound checksum.

Compression

Many features optimize the size of the obfuscated payload. In some cases the output can be smaller than the original script.

Reliability

Robust test pipeline ensures the scripts Luna produces are free of obscure bugs. Updates ship without breaking existing scripts.

Effective Security

One step ahead of every attacker

We're actively hardening Luna during this beta. Our goal is that even determined, targeted attempts to attack the obfuscator fail to defeat the outer security measures, let alone recover the original code of a script.

We continually gather intelligence on attackers to pre-mitigate attempts to defeat our security, employing the newest algorithms and techniques so the difficulty of restoring original code becomes harder as attacker tooling becomes more sophisticated.

Dependability

FAQ

Frequently asked questions

Will my obfuscated script still run on Roblox?
Yes — the output is valid Luau and runs unmodified inside Roblox executor environments where loadstring/load is available. Just paste it into your executor.
Is my source code uploaded anywhere?
Yes. Obfuscation happens server-side: your script is sent to our API over HTTPS, queued as a job, and picked up by our backend worker to produce the output. Your browser never talks to our database directly and never sees any credentials, but the source code does leave your machine to be processed.
What happens if someone edits the obfuscated output?
With Tamper-Lock enabled, the script computes a rolling checksum of its own ciphertext and folds it into the decryption keys. Changing a single byte produces garbage and the script silently refuses to run.
Can the obfuscator handle large scripts?
Yes, up to 5 MB per script. Your file is uploaded to the job queue and processed on our backend; the page polls for the result and stays responsive while it waits.
