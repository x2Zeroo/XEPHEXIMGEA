PHASE 3 — IDENTIFIER PROTECTION

ปรับปรุง identifier renaming ให้แข็งแรงกว่า random rename ธรรมดา

ต้องรองรับ:

- local variables
- local functions
- function parameters
- loop variables
- temporary variables
- aliases
- nested scopes
- shadowed variables

ต้องรักษา scope semantics อย่างถูกต้อง

ห้าม rename:

- Roblox/Luau reserved keywords
- identifiers ที่ต้องคงชื่อเพื่อ compatibility
- global APIs ที่จำเป็น
- string contents
- property names ที่เป็น string
- RemoteEvent/RemoteFunction names ที่ถูกเข้าถึงแบบ string
- identifiers ที่อยู่ใน context ซึ่งการ rename จะเปลี่ยน behavior

ใช้ชื่อที่มี distribution ไม่ predictable

รองรับหลาย naming strategy เช่น:

- short identifiers
- Unicode-safe identifiers เฉพาะเมื่อ runtime รองรับ
- mixed identifier patterns
- scope-dependent naming
- deterministic seeded naming
- randomized naming

ต้องมี seed เพื่อให้ผู้พัฒนาสามารถ reproduce output เดิมได้

==================================================
PHASE 4 — STRING PROTECTION

สร้างระบบปกป้อง string literals หลายระดับ

รองรับ:

- escaped representation
- numeric representation
- chunk splitting
- concatenation
- table-based storage
- indexed lookup
- per-string transformation
- per-group transformation
- delayed reconstruction

อย่าใช้ decoder รูปแบบเดียวกับทุก string

ควรสุ่ม strategy ตาม seed

ตัวอย่าง concept:

String A → strategy 1
String B → strategy 3
String C → strategy 2
String D → strategy 5

แต่ต้องไม่ทำให้ runtime overhead สูงเกินจำเป็น

อย่าถอด string ทุกตัวตอนเริ่ม script ถ้าไม่จำเป็น

ใช้ lazy reconstruction สำหรับ string ที่เหมาะสม

มี cache เพื่อไม่ decode ซ้ำโดยไม่จำเป็น
